# AgentLink 电脑局域网 Host

## 本机快速使用

1. 手机与电脑接入同一 Wi-Fi。安装 `artifacts/agentlink/AgentLink-1.3.0-android.apk`。
2. 电脑双击项目根目录的 `启动局域网连接.command`，保持终端运行。已有 Host 正在运行时无需重复启动。
3. 启动文件会自动打开电脑管理页。已有服务可用浏览器打开 `~/.agentlink/device-manager.html`。
4. 手机打开 App，自动搜索附近电脑；点击电脑名称。
5. 核对手机与电脑管理页显示的 **8 位数字完全一致**，在电脑点击“**两端数字一致，允许连接**”。手机会自动进入工作台，可选择 Codex 或 CodeBuddy。

以后打开 App，直接点“已配对的电脑”即可重连，无需再次填写地址、扫码或在电脑批准。App 会验证保存的电脑证书，网络请求通过加密连接发送独立设备凭据。电脑 IP 改变时，重新启动 Host；手机发现新地址后仍使用原电脑身份，草稿和未确认消息按身份保存。

电脑管理页可以拒绝新请求或撤销已有手机。撤销对新连接方式立即生效，手机需要重新在电脑获批。电脑证书或私钥损坏时会停止启动，不会悄悄更换身份；不要删除 `~/.agentlink/device-link` 来尝试修复网络问题。

## 扫码与旧 HTTP 方式

找不到电脑时，可在 App 点击“扫码或手动连接”，用电脑上的 `~/.agentlink/agentlink-lan-pairing.html` 二维码配对。这个兼容入口仍使用原有 HTTP 和共享配对码，只适合可信局域网；不会自动升级成独立设备授权。电脑管理页撤销手机不会撤销此前另行获得的共享配对码。

App 重启后，已保存的 HTTP 连接会显示“重新连接已保存的局域网电脑”；确认当前 Wi-Fi 与电脑地址后即可恢复，无需重新扫码。配对码保存在设备安全存储中。切换 Wi-Fi 或电脑 IP 改变时，重启电脑 Host 并重新扫码。

如果连接失败，先用手机浏览器打开终端显示的 `http://电脑IP:3106/health`。应显示包含 `status: ok` 的 JSON。无法打开时，检查电脑防火墙是否允许此 Host、Wi-Fi 是否启用了访客/AP 隔离、两端 VPN 是否拦截局域网。手机不能使用 `127.0.0.1` 或 `localhost` 代替电脑 IP。

Codex 和 CodeBuddy 共用一个 Hub 地址和二维码。这里控制的是通过 HAPI Runner 启动/接管的 CLI 会话，不能据此声称已同步 CodeBuddy IDE 中所有旧对话。

## 命令行启动

默认启动方式保持不变：Host 使用 HAPI relay，手机需要受信任的 HTTPS 地址。若手机和电脑在同一受信任局域网内，可显式启用 LAN 模式：

```sh
bun scripts/dev/agentlink-host.mjs --lan '/你的项目完整路径'
```

LAN 模式只监听所选物理网卡的 RFC1918 IPv4 地址，Host 与 Runner 也使用该地址连接 Hub；同时强制关闭网络 relay。它会选择唯一的非虚拟地址，并在 Hub 与 Runner 都就绪后显示 `hapicompanion://bind` 终端二维码。二维码中的配对码能访问电脑会话，不要截图、转发或在不受信任的网络中使用。

有多个物理网卡时，脚本会列出候选地址并停止，避免把 VPN 或错误网卡当作 LAN。明确选择已分配给电脑的地址：

```sh
bun scripts/dev/agentlink-host.mjs --lan --lan-ip 192.168.1.20 '/你的项目完整路径'
```

脚本还会在 `AGENTLINK_HOME`（默认 `~/.agentlink`）生成仅本机可读的 `agentlink-lan-pairing.html`（权限 `0600`）。用浏览器打开该本地文件即可扫码；页面内嵌二维码，不请求第三方资源。

新设备连接使用所选 LAN 地址的 TLS 3107 端口，UDP 3108 用于同子网发现；电脑管理页只监听 `127.0.0.1:3109`。旧 HTTP 入口使用 3106。新连接不需要购买域名或配置公网 HTTPS；证书由电脑生成，在两端核对数字后固定身份。请勿把电脑管理页链接转发出去。

自动发现失败时，检查防火墙是否允许 UDP 3108 和 TCP 3107，以及 Wi-Fi 是否开启访客/AP 隔离。广播通常不能穿过路由器、VPN或不同子网；扫码入口保留用于排障。不要在系统浏览器忽略证书警告来验证新连接；App 会执行自己的证书身份校验。
